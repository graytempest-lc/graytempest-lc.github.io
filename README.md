# L星团快讯

科技、开发与本地 AI 简报。公开站点：https://graytempest-lc.github.io/

## 内容与构建

Astro 静态站点。内容源、模板与生成产物分离，线上没有 Node 服务或数据库。

- `content/editions/YYYY-MM-DD.json`：每期唯一内容源，包含完整新闻、来源、显示日期、稳定锚点和速览。
- `src/components/` 与 `src/layouts/`：共用版面。`src/pages/` 生成首页、旧日期 URL、归档、RSS 视窗与本站 RSS。
- `public/sol3/`：已有月历、黄历与来源模块。保留其模型、待核边界和许可。`news-data.mjs` 中的前三条摘要从内容源生成。
- `data/feed-sources.json`：公开 RSS 白名单及许可。`data/feeds-cache.json`：仅标题、署名、时间和链接的成功快照。
- `dist/`：构建输出，不手工修改、不提交。

使用 Node 24.22.1 和锁文件：

```
npm ci
ASTRO_TELEMETRY_DISABLED=1 npm run check
npm run dev
```

`npm run check` 验证内容和 RSS 安全边界、构建站点、检查旧日报语义指纹、所有本地链接和锚点、首页与最新一期一致，以及本站 RSS。历史 10 期保留原有 112 条，过去不足 15 条的刊期不补造内容。语义指纹只在获准更正对应历史正文时审查更新。

## 每日发布

1. 从最新 main 开始，确认当天是否已有一期，不能覆盖其他并行变更。
2. 按已核第一手来源编辑当期 JSON；目标 15 条，实际不足时在 introduction 说明。至少对比近 7 期去重。
3. `editionDate` 是东八区刊载日，和每条事件日、来源日期分别记录。未核日期用 null，不从刊期猜测。每条使用稳定 id，保留来源、实际影响及限制。
4. 设置 status 为 published；draft 不出现在首页、日历、归档或 RSS。补发旧刊期不使首页倒退，前后期指向实际存在的刊期。
5. 运行 `npm run publish:prepare`（受限机器设 `ASTRO_TELEMETRY_DISABLED=1`），查看差异后提交内容源。该命令刷新 RSS；单个外部源失败不阻断日报发布。
6. main 推送触发 GitHub Actions，安装锁定依赖、恢复 RSS 成功缓存、刷新来源、检查并构建 dist，然后部署 GitHub Pages。
7. 按本次准确提交 SHA 查看工作流和部署终态，再打开公开首页、当期 URL、归档和 RSS 验收。提交成功不等于已经上线。

站点 Pages 的 Source 使用 GitHub Actions，站点根路径是 `/`。没有增加或修改现有日报任务的时间表；每日编辑发布由原有任务负责。只合并已授权变更，禁止强推和覆盖并发提交。

旧 HTML 稿件兼容导入：`npm run import:legacy -- /path/YYYY-MM-DD.html`，之后检查并构建。已有 JSON 默认拒绝覆盖，需要明确 `--replace`。`tools/build-calendar.mjs` 仍可生成数据，但正常构建不会反向解析 HTML，也不会用一期日报覆盖首页。

## RSS 视窗

首版来源为 Go Blog、Kubernetes Blog、web.dev，均有公开 feed 和 CC BY 4.0 许可依据（见来源配置）。仅展示原文标题、已有署名、准确来源时间和链接，不复制正文或图片，也不混入本站编辑精选。

只在发布构建时抓取，不在访客浏览器跨域读取，不带访客或账号资料。每源最多 5 条，支持条件请求、15 秒超时、3 MiB 解压后体积上限及同白名单 HTTPS 重定向。拒绝 DTD、实体声明、过深 XML、危险链接和非白名单条目；模板以文本转义输出。获取失败保留上次成功快照，超过 7 天隐藏条目。无 JavaScript 时页面仍显示明确的最近成功获取时间。

Actions 的主分支缓存保存最近成功快照；PR 检查不更新该缓存。没有增加独立高频抓取时间表。本站 `/rss.xml` 按“一期一条”输出；由于历史只有刊载日，订阅时间统一为东八区该日零点，而非宣称精确发布时间。

## Sol3 日历维护

首页保留完整月历、已核黄历条文和最新日报。不得直接用日报覆盖 index，也不得把局部条文写成完整择日结论。

月历按东八区民用日显示。2026 年中国大陆放假/调休来自国办发明电〔2025〕7号；新闻按本站刊载日归档，不是事件发生日。农历与节气仅核对 2026 年，未收录年份不套旧数据。新增年份须先核验历法、节假日和天文模型。

最终宜、忌保持空值，不是完整择日建议。节气时刻来自 MIT 许可的 Astronomy Engine 2.1.19 本地计算；源码与许可位于 `public/sol3/vendor/`。交节日保留前后两个日级条件，估算时刻不使待核内容变成确定结论。原典、许可和范围见公开 `sol3/sources.html`。

涉及日历逻辑的修改需回归：月份切换、无日报日期、非法/越界日期、跨年、交节前后、手机布局、键盘导航、迟到异步结果和反复选日；不能只看构建通过。
